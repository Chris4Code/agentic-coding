## Per-subtopic findings — compressed

- 🟢 **OpenAI's ChatGPT Retrieval Plugin** — the `/upsert`/`/query`/`/delete` endpoint spec is confirmed exactly against the repo itself, but the framing was outdated: OpenAI discontinued the ChatGPT plugins ecosystem in April 2024 (superseded by Custom GPTs/Actions), confirmed via the repo's own `docs/deprecated/plugins.md`. **Chapter corrected** to frame this as a legacy reference implementation rather than a live pattern, with a `Research Note:` clarifying that any resemblance to MCP is editorial observation, not documented lineage.
- 🟢 **`text-embedding-3-large` dimensionality (3,072) / `-small` (1,536)** — confirmed exactly against OpenAI's own docs. A genuine nuance was found and added: both v3 models support a `dimensions` truncation parameter (Matryoshka representation learning), so "dimension matching" is really against whatever dimensionality was requested at embedding time, not just "the model" in the abstract. **Chapter updated** with this nuance (a strengthening addition, not a correction of an error).
- ⚪ **"Dual-Embedding" / "Hybrid-Embedding" architectures — not corroborated as an established pattern.** No paper, vendor doc, or case study describes this specific local-BERT/progressive-cloud-partition query-routing scheme. "Hybrid embedding" in the real literature means something else entirely (sparse+dense fusion, e.g. BGE-M3). The individual building blocks are real; the named combination is not. **Chapter annotated** with a `Research Note:` disambiguating from the real "hybrid embedding" concept and flagging this as a coherent-but-synthesized design, not documented practice.
- 🟢 **RRF and BGE-Reranker** — no surprises. RRF traces to Cormack, Clarke, Büttcher (SIGIR '09) and is confirmed in production via Azure AI Search's hybrid search docs. BGE-Reranker is a real BAAI/FlagEmbedding model family. **Left unchanged** — well corroborated.
- 🟢/🟡 **Cache-Augmented Generation (CAG)** — confirmed as a real, named concept with a specific paper ("Don't Do RAG," arXiv:2412.15605). The "~90%" figure isn't from the CAG paper itself (its abstract states no percentage) — it traces to the standard Anthropic/OpenAI cache-read discount, which is a reasonable but indirect attribution. Real limitations found (context-window ceiling, non-trivial cache-write cost, staleness on updates) that the chapter's caveat didn't mention. **Chapter corrected** to attribute the 90% figure precisely and add the tradeoffs.
- ⚪ **The chapter's own "three-tier hybrid architecture" (Cold/CAG + Warm/local-BERT + Hot/cloud-embedding) — the most important finding, not an established pattern.** Hot/warm/cold *vector storage* tiering is real but tiers by storage latency/cost, a different axis entirely. A genuine, better-corroborated two-tier analogue exists (CAG for stable "core" + RAG for dynamic "long-tail," found in multiple 2025–2026 engineering blog posts). But the chapter's specific three-way combination — built by layering the unconfirmed Dual-Embedding scheme under CAG — appears nowhere as a documented, deployed system. **Chapter annotated** with a `Research Note:` making this explicit: technically sound and buildable from real primitives, but not something practitioners would currently recognize by this name.
