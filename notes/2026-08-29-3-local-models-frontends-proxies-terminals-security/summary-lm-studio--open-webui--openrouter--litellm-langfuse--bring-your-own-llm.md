## Per-subtopic findings — compressed

- 🟢 **LM Studio** — proprietary/closed-source desktop app (Element Labs, Inc.), Electron GUI + bundled **llama.cpp** and **MLX** engines, GGUF/MLX only (no raw safetensors/AWQ/GPTQ). Local server on :1234 speaks **both OpenAI** (`/v1/chat/completions`, tools, structured output) **and Anthropic** (`/v1/messages`, since **v0.4.1**) wire formats → drop-in local backend for Claude Code (`ANTHROPIC_BASE_URL=http://localhost:1234`). **MCP host since v0.3.17 (2025-06-25)** — servers in `~/.lmstudio/mcp.json`, per-call confirmation dialog, OAuth 2.1 for remote servers, MCP tools reachable through the API. `lms` CLI (open source, MIT) + headless mode (secondary sources call it `llmster` — 🟠). Speculative decoding first-class. **License (🟢):** always free for personal use; **free for commercial/work use since 2025-07-08** (no form, no contract); reverse-engineering/redistribution prohibited, liability capped $50; paid Teams/Enterprise only for collab/SSO/model-gating. Recent version-gated features (tensor parallelism, MTP) 🟠 — version numbers disagree.
- 🟢 **Open WebUI** — self-hosted ChatGPT-style web frontend, **no models of its own**. SvelteKit + FastAPI + SQLAlchemy + Redis + pluggable vector stores. Connects to **Ollama** (native) or any **OpenAI-compatible** endpoint (→ sits in front of LiteLLM/OpenRouter/vLLM/llama.cpp). Extensions: **Tools** (function calling), **Functions** (Pipes/Filters/Actions, modify the app), **Pipelines** (sidecar service). MCP via **`mcpo`** (MCP→OpenAPI proxy); native MCP reportedly ~v0.6.31 (🟠 single source). RBAC (Admin/User + permission groups), LDAP/OIDC SSO, SCIM 2.0. **License (🟢):** MIT → BSD-3-Clause (early 2025) → **"Open WebUI License" from v0.6.6 / 2025-04-19 = BSD-3 + branding-protection clause + CLA**. May remove "Open WebUI" branding only if deployment is **≤ 50 users / any 30-day window**, OR you're a permitted contributor, OR you hold an enterprise license. Code through **v0.6.5 stays pure BSD-3** (not retroactive). Practical read: still free for self-hosting and internal/team use; only constraint is white-labeling a >50-user deployment. **Role:** human-facing chat/admin surface, *not* a coding agent (no repo checkout, no edit loop, no shell).
- 🟢 **OpenRouter** — cloud aggregation API, one OpenAI-compatible endpoint in front of **500+ models / 80+ providers** (homepage; prior note's "650+" is stale). **Fee model (🟢, verified from OpenRouter docs):** *no markup on inference* (pass-through token pricing); **credit-purchase fee 5.5% + $0.80 min (card), 5% (crypto)** — a payment fee on top-ups, not usage; **BYOK = 5% of OpenRouter list price** after a free monthly allowance of **$25,000** (PAYG) / **$200,000** (enterprise) of list-price inference; opt-in prompt logging → **1% usage discount** (default = zero logging, metadata only). Also exposes an **Anthropic Messages endpoint** (`/api/v1/messages`). Routing: price-weighted load-balance + failover; `:nitro` (throughput), `:floor` (price); `order`/`sort`/`only`/`ignore`/`max_price`. **Privacy (🟢):** `data_collection: "deny"`, **`zdr: true`** (Zero Data Retention endpoints only), enterprise in-region routing (`eu.` / `us.openrouter.ai`) — the prior note's "US routing / privacy caveat" is only true if you don't set these. Prompt-caching pass-through with ~10-min provider-sticky routing. Free-tier (`:free`): ~20 rpm, ~50/day until $10 ever spent then 1,000/day — 🟡 (third-party trackers).
- 🟢 **LiteLLM + Langfuse** — **LiteLLM** = two products in one repo: the Python **SDK** (normalizes 100+ providers to OpenAI call shape, in-process) and the **Proxy / AI Gateway** (:4000, OpenAI-compatible server + **virtual keys**, budgets, rate limits, routing/fallbacks/load-balancing, caching, Admin UI; virtual keys/budgets need Postgres). **Virtual keys** = `sk-…` issued by the proxy; real upstream provider keys stay server-side. **Anthropic pass-through** at `/anthropic/...` is how Claude Code points at LiteLLM. **License: MIT** for the full OSS core (proxy, UI, virtual keys, budgets, spend, fallbacks, logging); paid **Enterprise** adds SSO/audit-logs/JWT/guardrails (~$250/mo 🟠). **Langfuse** = OSS LLM **observability/tracing/eval/prompt-management** (traces of multi-step agent runs, cost/latency, LLM-as-judge, prompt registry); v3 on ClickHouse+Postgres+Redis+S3. **June 2025: moved ALL product features to MIT** — only a thin EE set (project RBAC, data-masking, audit logs, SCIM) stays commercial; MIT self-hosting has no seat/retention/usage caps. **Acquired by ClickHouse, Inc. 2026-01-16** (OSS commitment stated unchanged). **Native integration:** LiteLLM has a built-in Langfuse callback (`success_callback: ["langfuse"]`) → a trace per LLM call; OSS-to-OSS, neither enterprise tier needed. Pairing = LiteLLM as control plane + Langfuse as observability plane, fully self-hostable/MIT — vs OpenRouter which is hosted SaaS, not self-hostable, no deep tracing. (Raw file has a mermaid diagram of the stack.)
- 🟡 **Bring Your Own LLM / BYO-key** — agentic tools just need an endpoint speaking OpenAI `chat/completions` or Anthropic `messages`. llama.cpp/vLLM/Ollama/LM Studio all expose OpenAI `/v1`; **LM Studio (🟢), and llama.cpp/vLLM (🟠 — one gist)** also expose Anthropic `/v1/messages`. **Claude Code:** 4 env vars — `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL` — point it at LM Studio/Ollama directly, at **LiteLLM's `/anthropic` pass-through**, or use **claude-code-router** (3rd-party MIT, Anthropic⇆other translation + per-task routing). **Aider:** `--model ollama/... --openai-api-base ...`. **Cline/Roo/Continue:** "OpenAI Compatible" provider. **Frictions (🟡):** the `/v1` path (most common misconfig), tool-calling format/template reliability on local models, Anthropic `cache_control` is a no-op on most local servers (system prompt re-processed every turn), context length (Claude Code is context-heavy — LM Studio advises ≥25K), `ANTHROPIC_SMALL_FAST_MODEL` must also resolve.
- 🟢/🟡 **Terminals & "agent sandbox"** — the section's `CONTENT-KEY-SUBJECTS` lists **Warp (Oz), Ghostty, Alacritty, WezTerm**.
  - **Warp** — Rust GPU terminal repositioned as an "Agentic Development Environment". **"Oz" resolved (🟢): a real named product** — Warp's **cloud agent-orchestration platform, launched 2026-02-10**. Runs hundreds of agents in parallel, each in a **Docker container** (container + repos + startup commands); **multi-harness** (Claude Code, Codex, Warp Agent side by side); **cloud-hosted by default, self-hosted for enterprise**, local via CLI. **Not a codename, not a model.** Pricing: Free / Build $20 / Max $200 / Business $50-user (SOC2, ZDR, SAML) / Enterprise. **BYO provider key on Build+Max; BYO-LLM managed inference + enforced ZDR + on-prem Oz on Enterprise.**
  - **Ghostty** — Mitchell Hashimoto's terminal, **1.0 on 2024-12-26, MIT**, Zig, native platform UI, GPU (Metal/OpenGL). **Pure terminal — no AI, no agent.** A *host* for agent CLIs, not a participant.
  - **Alacritty** — minimal GPU (OpenGL), Rust, TOML config only, **no tabs/splits by design** — multiplexing delegated to tmux.
  - **WezTerm** — GPU, Rust, Lua config, **built-in multiplexer** (tabs/splits/workspaces + remote SSH "domains", persistent) — can replace tmux; best fit for running many agent PTYs side by side.
  - **Why it matters:** agents stream large output (diffs, logs) → GPU renderers avoid PTY stalls; long runs need scrollback; parallel agents need multiplexing. **"Agent sandbox"** = running an agent (shell+network+write) in an isolated container/micro-VM: devcontainers/Docker (weakest), gVisor (Daytona), Firecracker micro-VMs (E2B, strongest), hosted (E2B / Daytona / Modal / Warp Oz / hopx.ai BYOC), plus local seccomp/Landlock/Seatbelt "sandbox" modes in Claude Code etc.
- 🟢/🟡 **Security + key management** —
  - **Keys:** every tool reads keys from env vars → leak into shell history, committed `.env`, MCP/agent config files, CI logs. Mitigations: `.gitignore` the `.env`; inject at runtime from **1Password (`op run`) / HashiCorp Vault / cloud secret managers / `sops`+`age`**; **push protection + secret scanning** (gitleaks, trufflehog); short-lived, **per-project** keys. Git history is permanent → a leaked key must be **revoked + rotated**, not just un-committed.
  - **Gateways reduce blast radius:** LiteLLM virtual keys / OpenRouter BYOK keys keep real provider keys in one place; developers get revocable, budgeted, model-scoped tokens.
  - **Self-hosted inference servers ship with NO AUTH by default (🟢):** Ollama, `llama-server`, vLLM. llama.cpp/vLLM added optional `--api-key` (off unless set). **Ollama exposed-instance problem is real and documented (🟡):** ~100k–300k Ollama servers on public IPs (Shodan ≈ 270k on port 11434); **CVE-2025-63389** (Ollama ≤ v0.12.3, unauthenticated model-management endpoints — pull/push/delete models, run inference on victim hardware). Correct posture: bind `127.0.0.1`/WireGuard, reverse proxy + auth for remote, firewall the raw port, treat like an unauthenticated database.
  - **Local-model privacy argument + caveats:** "nothing leaves the machine" — *unless* a router has cloud fallback enabled (OpenRouter, LiteLLM fallbacks, claude-code-router, Warp Oz can all silently fall back to cloud), tool telemetry is on, or a self-hosted Langfuse/LiteLLM trace DB is persisting prompts+completions (`turn_off_message_logging` to avoid).
  - **Prompt injection / excessive agency:** OWASP LLM01 + LLM06 (🟢). **Local models make this sharper** — an autonomous agent with shell+network+write driven by a local model has **no provider-side safety filter** between an injected instruction and `rm -rf` / exfil `curl` / `git push` of secrets. Mitigations are architectural: sandbox, least-privilege tools, human approval on write/exec, egress allow-list, secrets excluded from the agent's env.
