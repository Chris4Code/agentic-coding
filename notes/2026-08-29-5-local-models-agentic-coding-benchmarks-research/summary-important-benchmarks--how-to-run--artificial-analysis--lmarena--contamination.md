## Per-subtopic findings — compressed

### 1. The benchmarks that matter (🟢 unless noted)

- **SWE-bench** (Jimenez et al., ICLR 2024, Princeton) — 2,294 real Python GitHub issues; produce a patch, repo's own tests run (`FAIL_TO_PASS` must pass, `PASS_TO_PASS` must not regress); score = **% resolved (pass@1)**. `SWE-bench Lite` = 300-task subset.
- **SWE-bench Verified** — 500-task human-filtered subset, **OpenAI**, Aug 2024, with the original authors: 93 pro Python devs screened out under-specified tasks / bad tests / broken envs. **The de-facto headline "agentic coding" number.** Contamination-resistance **low** — all public repos with public fixes; **OpenAI itself flagged verbatim training-data reproduction in Feb 2026** (🟡, not read directly).
- **SWE-bench Pro** (Scale AI, [arXiv:2509.16941](https://arxiv.org/abs/2509.16941)) — ~1,865 long-horizon tasks / 41 repos, split **public** (11 repos, GPL to deter training) / **held-out** (12 repos, leaderboard-only) / **commercial** (18 proprietary). The variant 2026 vendors (incl. Qwen) increasingly report. Contamination-resistance medium-high for held-out/commercial.
- **Terminal-Bench** (Stanford + Laude Institute) — English instruction + Docker container + verification script; agent gets a shell, graded outcome pass/fail. **1.0** ≈ 100 tasks; **2.0** (Snorkel + Stanford + Laude) = 89 curated verified tasks; **2.1** fixed 28 of them + continuous validation — **the version Artificial Analysis uses**. "Terminus" = the reference agent; submissions are (model × scaffold). New **`harbor`** harness for large parallel runs.
- **Aider polyglot** (Aider project, Dec 2024) — **225 hardest** Exercism exercises × **6 languages** (C++, Go, Java, JS, Python, Rust). One attempt + **one retry** with test output fed back. Two metrics: **% correct** (`pass_rate_2`) and **% valid edit format**. Explicitly tests *editing existing code*, not just coding. Leaderboard still updated (Aug 2026).
- **LiveCodeBench** (v5: 880 problems May'23–Jan'25; v6: 1,055, to Apr'25) — LeetCode/AtCoder/Codeforces problems **tagged by release date**; evaluate only on problems after the model's cutoff → genuinely contamination-controlled for the recent window. pass@1/pass@5.
- **Contamination-resistant refreshers:** **SWE-bench-Live** (Microsoft, [arXiv:2505.23419](https://arxiv.org/abs/2505.23419)) — auto-curated tasks from issues since 2024, refreshed monthly; **SWE-rebench** (Nebius) — 21k+ mined tasks, monthly leaderboard splits by `created_at`, fixed scaffold, explicit contamination tracking. SOTA agents score notably lower on both than on static SWE-bench.
- **Beyond Python:** SWE-bench **Multimodal** (~517 test tasks, 17 JS front-end libs, images in the task), SWE-bench **Multilingual** (300 tasks, 9 langs), **Multi-SWE-bench** (ByteDance, 1,632 tasks, 7 langs).
- **Legacy / saturated:** HumanEval (164 tiny fns), MBPP (~1k), BigCodeBench (1,140, multi-library). Frontier models 96–98% on HumanEval — **only meaningful now for small local models (~1B–30B)** and regression checks. Contamination-resistance **very low**.
- **Computer-use:** **OSWorld** (369 tasks in an Ubuntu VM) / **OSWorld-Verified** (July 2025 bug-fix revision) — GUI agents, adjacent to coding, appears on 2026 cards next to Terminal-Bench.
- **Reasoning-adjacent, quoted alongside coding:** **GPQA Diamond** (198 hard science MCQs), **AIME** (year-stamped math), **LiveBench** (monthly-refreshed, no LLM judge, has a coding category).
- **Load-bearing framing point — "harness matters":** an agentic score is **(model × scaffold × settings)**, not a model property. Anthropic got Claude 3.5 Sonnet from 45%→**49%** SWE-bench Verified with a *minimal two-tool* scaffold, some points purely from tool-description wording ([anthropic.com/engineering/swe-bench-sonnet](https://www.anthropic.com/engineering/swe-bench-sonnet)). `mini-SWE-agent` (~100 lines, bash-only) reports **>74%**. 2026 model cards specify the harness ("Claude Code harness at 256K", "OpenHands scaffold") because the number is meaningless without it. → **compare local models yourself with scaffold + settings held fixed; treat cross-vendor tables as directional only.**

### 2. How to run them (🟢 commands verified against repo READMEs unless flagged 🟠)

- **Universal local-endpoint pattern:** nearly every harness routes through **LiteLLM or the OpenAI SDK**. Set `OPENAI_API_BASE=http://localhost:8000/v1` (+ a dummy key) and use a provider-prefixed model name: `openai/<name>`, `hosted_vllm/<name>`, `ollama/<name>` / `ollama_chat/<name>`. Exact env var / flag (`OPENAI_API_BASE` vs `OPENAI_BASE_URL` vs `--api-base`) varies per tool — 🟠 check each README; the routing itself is real and consistent.
- **SWE-bench = two steps.** (1) **Generate predictions** with an agent **scaffold** — this is where the local model plugs in: `mini-swe-agent` (`pip install mini-swe-agent`; `mini-extra swebench`; `--model` / `MSWEA_MODEL_NAME`; LiteLLM under the hood), or SWE-agent / OpenHands / Agentless / Moatless. (2) **Grade** with the official Docker harness: `pip install swebench`, then `swebench eval verified -p <predictions.json> --run-id <id> -j <workers>` (older `python -m swebench.harness.run_evaluation --dataset_name … --predictions_path … --run_id … --max_workers … [--instance_ids …]` still works). `--predictions_path gold` sanity-checks. ARM: `--namespace ''`. **Needs x86_64, ≥120 GB disk, Docker.** Verified = ~500 Docker-heavy tasks × many agent steps → hours + tens of GB images; most run a subset or Lite's 300. **Hosted alternative: `sb-cli`** (grading on SWE-bench's AWS, no local Docker).
- **Terminal-Bench:** `pip install terminal-bench`; `tb run --agent terminus --model <litellm-name> --dataset-name terminal-bench-core --dataset-version <v> --n-concurrent 4`; Docker per task. 🟠 whether `tb run` or the newer `harbor` is canonical for TB 2.1 — check the repo.
- **Aider polyglot:** harness inside the Aider repo (`benchmark/`), runs **in Docker** (`./benchmark/docker_build.sh` → `./benchmark/docker.sh` → `./benchmark/benchmark.py <run> --model <name> --edit-format whole --threads 10`). Model names = Aider CLI format (LiteLLM). Leaderboard submission is a manual maintainer PR.
- **LiveCodeBench:** `python -m lcb_runner.runner.main --model <name> --scenario codegeneration --release_version release_v6 --start_date YYYY-MM-DD --end_date YYYY-MM-DD --evaluate`. Open models via vLLM (`--tensor_parallel_size`). 🟠 exact local-endpoint registration — check `lcb_runner/lm_styles.py`.
- **Multiple-choice / knowledge (HumanEval, MBPP, GPQA, MMLU-Pro):** **lm-evaluation-harness** (EleutherAI — powered the retired HF leaderboard; `local-completions` backend hits a local server), **inspect-ai** (UK AISI — now the standard for *agentic* evals), **OpenBench / `bench`** (Groq, built on inspect-ai, one canonical impl per benchmark, `bench eval <name> -M <model-args>`, works with Ollama / any OpenAI-compatible server).

### 3. artificialanalysis.ai — 🟢 methodology / 🟡 company facts

An **independent AI benchmarking firm** (founded 2023, Micah Hill-Smith & George Cameron) that runs its **own** evals and its **own** performance measurements rather than republishing lab numbers.
- **Artificial Analysis Intelligence Index** — a **composite** re-versioned as the eval set changes. **v4.1.x** (current, Aug 2026) = weighted over 4 categories: **Agents 34%**, **Coding 24%** (Terminal-Bench v2.1 16% + SciCode 8%), **Scientific Reasoning 24%** (HLE, GPQA Diamond, CritPt), **General 18%**. Trend across versions: away from saturated MCQ, toward agentic/terminal tasks. Has a coding-specific view.
- **The part relevant to a self-hosting chapter — independently measured per-endpoint performance.** For every hosted endpoint (same open model across Together / Fireworks / DeepInfra / Groq / Cerebras / the model's own API / …): **output tokens/sec**, **time-to-first-token** (and time-to-first-*answer*-token for reasoning models), **end-to-end latency**, **price** ($/M input, $/M output, blended ~3:1 🟡). Method: synthetic prompts from Google Cloud `us-central1-a`, 8×/day for 1k/10k-input workloads, reported as trailing-72h P50.
- **Good for:** picking a hosted provider for an open model; a **sanity-check reference** for a local rig's tok/s. **Limits:** measures **hosted endpoints, not your box** (your tok/s depends on your GPU/quant/context/engine); the Index is a composite that hides task-specific strengths; index-version changes move scores independent of any model change.

### 4. lmarena.ai — 🟢 mechanism / 🟡 company & funding

**Crowdsourced human-preference** eval: user prompts, two **anonymous** model responses side-by-side, votes; identities revealed after. Votes → a statistical ranking → an **Arena Score** per model with 95% CI.
- **Origin:** started 2023 as **Chatbot Arena** by **LMSYS** (UC Berkeley — [arXiv:2403.04132](https://arxiv.org/abs/2403.04132), ICML 2024). **April 2025:** incorporated as **Arena Intelligence Inc.**, rebranded **LMArena**, new UI May 2025. **$100M seed** May 2025 (a16z + UC Investments, ~$600M valuation); **$150M Series A** reported Jan 2026 (🟡). The domain `lmarena.ai` now **redirects to `arena.ai`**. Independence caveat: a **VC-backed company that also partners with the labs it ranks** (pre-release model access).
- **Ranking:** Elo originally → **Bradley-Terry** (MLE over all pairwise outcomes) since early 2024; methodology open-sourced as **"Arena-Rank"** (JAX, closed-form CIs).
- **Style control:** regression covariates for response **length** and **markdown density** so a model can't win on formatting alone. **Default** for text/vision boards since May 2025.
- **Sub-arenas (13+):** Overall, Text, **Agent**, **WebDev** (model *builds a web app*, user votes on the rendered result — closest to agentic coding, but single-shot), Vision, Search, **Copilot Arena** (VS Code extension, two models' inline completions stacked, Tab-accept = vote — [arXiv:2502.09328](https://arxiv.org/abs/2502.09328)), image/video boards.
- **Critiques:** preference ≠ correctness (weak for code); sycophancy / style / vote-brigading; **"The Leaderboard Illusion"** ([arXiv:2504.20879](https://arxiv.org/abs/2504.20879), Apr 2025) — undisclosed **private best-of-N testing** by big labs (27 private Llama-4-era Meta variants cited) violating the Bradley-Terry unbiased-sampling assumption; **disproportionate battle traffic** to OpenAI/Google (~20% each) vs <30% for 83 open models combined; selective model retirement. LMArena disputed parts, published more policy afterward.
- **Good for:** real-world helpfulness/instruction-following signal at scale, hard to contaminate (live fresh prompts). **Not for:** coding correctness, agentic/tool-use capability.
- ⚠️ **Do not state a specific current cumulative vote count** — no primary figure confirmed (paper says >240k at write-up; site says "millions").

### 5. Contamination / reward hacking (brief) — 🟢 via cross-ref

Static scores are inflated by **training-data contamination** (test issues/patches/wording in the corpus) and **reward hacking** (incorrect patch passes a thin test suite; agent mines the fix from git history / GitHub / registries). This is *why* the refreshers (SWE-rebench, SWE-bench-Live, LiveCodeBench date windows, SWE-bench Pro held-out) and human-preference arenas exist. **`src/sw-factories.md` already covers the evidence in full** (arXiv 2606.16062: 28.5% of a SWE-bench Verified sample has test suites weak enough to pass an incorrect patch, +14.14 pp Pass@1 on hackable tasks; Poolside & Cursor admissions; SWE-Marathon) — the new section should point there in one sentence, not re-derive.
