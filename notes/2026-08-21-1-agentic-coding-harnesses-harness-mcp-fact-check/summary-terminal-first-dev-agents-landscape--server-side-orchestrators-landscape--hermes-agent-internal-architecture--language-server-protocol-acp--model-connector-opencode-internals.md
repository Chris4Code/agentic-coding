## Per-subtopic findings — compressed

1. 🟡 **Terminal-first dev agents landscape** — Goose/AAIF/"70+ extensions"/Aider all strongly corroborated verbatim. Two corrections found: "Pi / Kilo CLI" conflates two unrelated products from different teams into one bullet. "Cursor & Windsurf (Devin Desktop)" misleadingly implies Devin Desktop is a footnote to the Cursor-Windsurf pairing — in fact Cognition (Devin's maker) acquired Windsurf in July 2025 and rebranded it "Devin Desktop" in June 2026; Cursor is an unrelated third company. **Chapter corrected**: split Pi and Kilo CLI into two bullets, and reworded the Cursor/Windsurf bullet to reflect the acquisition/rebrand accurately.
2. 🟡 **Server-side orchestrators landscape** — Claude Cowork confirmed real and current (Anthropic, launched Jan 2026). OpenClaw/DeerFlow/Perplexity Computer (the "19-model" figure is a real, confirmed CEO quote) strongly corroborated. One correction: "Symphony" is presented as an independent OSS project but is actually OpenAI's own orchestrator for Codex agents — a materially different category. **Chapter corrected** to attribute Symphony to OpenAI.
3. 🟢/🔴 **Hermes Agent internal architecture — most consequential finding.** Most individual filenames/classes (`run_agent.py`'s `AIAgent`, `model_tools.py`, `toolsets.py`, `hermes_state.py` w/ SQLite+FTS5) are real and directly verified against the live repo. Two corrections: (a) the chapter's flat 6-file tree is wrong — `context_engine.py`, `context_compressor.py`, and `prompt_builder.py` actually live under an `agent/` subdirectory, and the real repo is far larger than six files; (b) the claim that skills are "retrieved via vector search" is very likely fabricated — both primary (`hermes_state.py`'s actual FTS5-only schema) and secondary sources confirm Hermes deliberately uses SQLite+FTS5 **keyword** search instead of vector search. **Chapter corrected**: file tree annotated as illustrative/simplified, vector-search claim replaced with the real FTS5 keyword-search mechanism, with a `Research Note:` explaining the correction.
4. 🟢 **LSP & ACP** — fully corroborated, no changes. All four JSON-RPC method names confirmed exact against the LSP 3.17 spec; ACP confirmed to originate from Zed Industries (Aug 2025), now co-developed with JetBrains.
5. 🔴 **Model Connector — OpenCode internals** — the Go-based `internal/llm` package is real, but belongs to the *superseded* `opencode-ai/opencode` (the loser of a 2025 naming dispute, whose creator moved to Charm/Crush), not the dominant `sst/opencode` (160k+ stars) that the chapter itself describes earlier in §1 — which is TypeScript/Bun with no `internal/llm` path. **Chapter corrected** to remove the now-inaccurate Go/`internal/llm` specifics and describe the connector concept generically instead.
6. 🟢 **MCP fundamentals** — fully corroborated against Anthropic's own announcement (Nov 25, 2024) and the official spec. No changes.
7. 🔴 **REST/OpenAPI MCP tooling** — `@modelcontextprotocol/server-openapi` **does not exist** (confirmed via direct npm registry 404 and a full listing of the official scope's 55 real packages). `openapi-mcp` on PyPI is real. **Chapter corrected**: replaced the fabricated npm package as "the dominant tool" framing with an accurate description of the real, unofficial third-party ecosystem, keeping the real `openapi-mcp` PyPI package.
8. 🟡 **GraphQL MCP tooling** — `graphql-mcp.com` and `mcp-graphql` both real. One correction: "Apollo's AI Gateway" is the wrong product name — Apollo's real product is "Apollo MCP Server." **Chapter corrected** to use the accurate name.
9. 🟢 **gRPC MCP tooling** — all three named tools (Redpanda's `protoc-gen-go-mcp`, `grpcmcp`, ConnectRPC) strongly corroborated. Minor imprecision: ConnectRPC's former name was "Connect," not literally "Buf Connect." **Chapter corrected** with the precise former name.
10. 🟡 **CLI/MCP generation tooling** — FastMCP `generate-cli`, Apify's `mcpc`, MCPLI, and `mcp-cli-adapter` all confirmed real (one correction: FastMCP's `generate-cli` is Python/`cyclopts`-only, no Node/`commander` support). "LobeHub's CLI-as-MCP" could not be corroborated, and its own source citation contains a literal `yourusername` placeholder — a strong sign of a fabricated/template citation. **Chapter corrected**: removed the FastMCP/`commander` claim and replaced the unverifiable LobeHub example with the real, verified `mcp-cli-adapter`/MCPLI examples already present.
