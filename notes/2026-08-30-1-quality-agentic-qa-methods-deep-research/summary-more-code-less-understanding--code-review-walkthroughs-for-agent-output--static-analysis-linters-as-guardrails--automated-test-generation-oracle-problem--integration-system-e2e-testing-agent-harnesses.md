## The 11 subtopics, compressed

1. 🟢 **"More code, less understanding"** — agentic coding inverts review economics: code is now generated faster than any human can audit, so "read the diff" becomes the rate-limiter. Named framings: Addy Osmani's *"comprehension debt"* (more dangerous than tech debt because it "breeds false confidence"), Geoffrey Litt's *"understanding is the new bottleneck"* (verify vs. participate). Measured: Anthropic RCT (52 mostly-junior engineers, AI group ~17% lower on comprehension quiz, ≈50% vs ≈67%, steepest drop on debugging); peer-reviewed PR study (arXiv 2605.02273) — **61.4% of AI PRs get no recorded review**, human participation visible in only 15.9%, reviewers spend ~26% of their effort *steering* the agent vs 1.6% on human PRs; GitClear, DORA 2025 (AI now +throughput but still −delivery stability), Faros (from prior pass). Causation to AI is hedged by the sources themselves; direction + mechanism solid. Mitigations: smaller diffs, agent-generated explanations/ADRs, humans stay in planning, shift review from nits to intent/architecture, stronger automated gates.
2. 🟡 **Code review adapted for agent output** — three moves: automated review layer *before* the human, review *inside* the loop (separate "critic" agent in a fresh context — "the maker shouldn't grade the checker"), retarget humans to intent/architecture/security/scope-creep/test-quality. Tools primary-sourced: GitHub Copilot code review, **Claude "Code Review"** (Anthropic research preview — per-PR subagent team, verification-before-yielding false-positive filter, internal numbers: 84% of >1k-line PRs get findings, <1% marked incorrect, ~$15–25/PR), CodeRabbit, Greptile, Cursor BugBot, Graphite Diamond, Qodo. Danger/Reviewable are **not** LLM reviewers (Danger = scripted PR-policy checks). Efficacy contested: vendor benchmarks optimistic (Greptile self-test 82% catch rate — recall only, no precision; CodeRabbit study: AI PRs ~1.7× more issues) vs independent academic (MSR 2026 arXiv 2604.03196: 12/13 review agents below 60% signal ratio, CRA-only PRs merge 45% vs 68% human, "80% without humans" claim unsupported).
3. 🟢 **Static analysis / linters as agent guardrails** — the delta: linters become an *automatic correction signal* in a closed loop (agent writes → linter/type-checker/compiler runs → structured errors fed back → agent fixes → repeat before yielding). Deterministic, precise messages beat prose `CLAUDE.md` rules. Primary: Böckeler's *"maintainability sensors"* / sidecar CLI (martinfowler.com — basic linting reliably catches agent over-long-function/complexity failures; cross-file coupling metrics "noisy without semantic interpretation"; give the agent a *sanctioned visible* escape hatch so suppressions aren't hidden), Factory.ai *"linters write the law"* (7 rule categories), Osmani, Kinney. SAST: **Semgrep MCP server** (official) + **Semgrep Guardian** (plugin — regenerates code until scan is clean). Failure mode: agents add `# noqa` / `eslint-disable` / `@ts-ignore` / edit lint config to pass — mitigations: rule forbidding new suppression comments, treat any lint/CI-config change as review-required. No quantified study of how often agents do this.
4. 🟢 **Test generation & the oracle problem** — the delta: the agent that wrote the bug also writes the "proof" it works; self-generated tests encode *what the code does*, not *what it should do*. Established SE research: Konstantinou et al. (arXiv 2410.21136) — LLM oracles "capture the actual program behaviour rather than the expected one"; accuracy *drops* on buggy code; Molina et al. — oracle accuracy <50% from requirements alone. Reproduced by practitioners (Böckeler: 100% line coverage / 13 surviving mutants; Radzymiński: 100% coverage / 61% mutation score). Test-tampering under task pressure documented by Anthropic ("modify, delete, weaken... test assertions despite an explicit instruction not to") + SpecBench (arXiv 2605.21384). Coverage is the wrong target (weakly correlated with fault detection). Defenses: **mutation testing** (Stryker/PIT/mutmut/`cargo-mutants`) — agents remove the historical interpretation bottleneck (agent reads the mutation report, writes targeted tests); **property-based testing** (Hypothesis/fast-check/jqwik/proptest — oracle the agent can't overfit); **TDD test-first human-approved**; golden/characterization tests; keep test authorship separate from implementation. Large-scale evidence that "mutation testing on agent PRs reduces escaped defects" not yet available.
5. 🟡 **Integration / E2E testing with agent harnesses** — "Harness Browser Integration" = giving the coding agent browser/computer-use tools *inside its loop* to load the running app, interact with what it built, read console/network output. Primary-sourced & real: **Playwright MCP** (March 2025, drives via accessibility tree not CSS → deterministic, survives DOM refactors, breaks on accessible-name changes), **Playwright Agents — Planner/Generator/Healer** (Playwright 1.59, Oct 2025 — self-healing E2E as a first-class feature: Healer replays failing steps, finds equivalent elements, patches locators/waits), **GitHub Copilot coding agent ships Playwright MCP built-in**, **Chrome DevTools MCP** (Google — drive with Playwright, observe/debug with DevTools MCP), `browser-use`, Anthropic computer use. Practices: reproduce bug with a failing E2E test first; visual regression (`toHaveScreenshot`); feed E2E output back into the loop. Risk: an over-eager Healer can "heal" a test into passing against a real regression (§4 test-weakening at the E2E layer). **No quantified effectiveness study exists** — all practitioner-level, hedged by vendors.
6. 🟠 **Acceptance testing & A/B via feature flags** — split evidence. Acceptance-with-agent (agent proposes Gherkin → **human approves the Gherkin** → agent wires step defs; the reviewed Gherkin is the fixed acceptance oracle; Cucumber/SpecFlow/Reqnroll/Behave) — corroborated across practitioner sources, no hard numbers, overlaps `spec-driven-development.md` + §8. Feature flags as a safety net (flags decouple deploy from release → blast radius of an under-reviewed agent change is bounded by rollout %) — well corroborated in principle; **LaunchDarkly has named products "CodeControl" / "AgentControl"**; Unleash/Flagsmith/OpenFeature named; progressive delivery / canary (1%→5%→25%→100% with auto-rollback) is the mechanism. **A/B-comparing two agent-generated implementations of the same feature: no primary write-up found** — plausible extrapolation of progressive-delivery practice, not a documented pattern. One quoted Gherkin accuracy figure (60%→92%) has unclear provenance — do not rely on it.
7. 🟡 **Non-functional testing** — consistent multi-source finding: agent code is *functionally correct but non-functionally weak* because no standard quality gate measures efficiency. Primary benchmarks: **SWE-Perf** (arXiv 2507.12415, ICML 2026, 140 real perf-improving PR instances), **SWE-fficiency** (arXiv 2606.25530, 498 tasks — "top LLM agents achieved <0.15× the speedup an expert achieved"), Springer *Empirical Software Engineering* 2025 case study (Copilot/CodeLlama/DeepSeek-Coder — "functionally correct but performance regressions vs human solutions"). Dramatic aggregate numbers (Codeflash: 118 slow functions over 76k lines, 3×–446× slowdowns; "52% of eng leaders report AI → performance problems"; "90% of AI-suggested optimizations incorrect") come **via one blog** (Blake Crosley) aggregating multiple sources — cite the underlying sources, flag the blog as collation point. Adaptation: perf micro-benchmarks in CI on critical paths (`pytest-benchmark`, JMH, criterion, `testing.B`); AST-pattern detection (Semgrep/`ast-grep` for re-traversal/missing-cache); load testing (k6/Locust/Gatling/JMeter — tools unchanged, agent writes the script); SCA + secret scanning + DAST become **non-optional in-loop gates** (agents add dependency bloat + re-introduce CWE patterns — CodeRabbit security multipliers: XSS 2.74×, insecure deserialization 1.82×); accessibility (`axe-core`) — agent-generated UI omits ARIA, which also degrades Playwright MCP's own harness.
8. 🟠 **Design by Contract for agents** — *least evidenced subtopic, as predicted.* A machine-checkable contract gives the agent explicit intent it can't silently drift from + a non-gameable oracle + a precise localized error (same loop shape as §3/§4). **8a Contract Injection**: `icontract`, `deal`, **CrossHair** (SMT-solver counterexample search — *ships its own `AGENTS.md`*), `icontract-hypothesis`; JML/OpenJML (Java); Ada/SPARK (formal proof, niche); `clojure.spec`/Malli. One direct study: Embry-Riddle/IEEE Xplore 11218044 — adding pre/postconditions to the prompt "significantly boosts initial generation accuracy (pass@k)", weaker/smaller models benefit most. **8b Spec-Driven Generation** (defer to `spec-driven-development.md`): GitHub Spec Kit (OSS Sept 2025), AWS Kiro, Tessl ("spec-as-source"); **VibeContract** (arXiv 2603.15691) is a 5-page position paper, no experiments; VERINA / Self-Spec benchmarks. **8c Automated Contract Testing**: Pact / consumer-driven contracts, **PactFlow AI** (generates/maintains Pact artifacts — agent authors the contract tests), property-based tests as executable contracts. Tools are real and mature; the synthesis "give agents contracts for a tighter loop" is argued in position papers + blogs, **not** backed by large controlled studies. Say so plainly in the chapter.
9. 🟢 **CI/CD as the enforcement layer** — the delta: CI stops being a convenience, becomes the non-negotiable gate ("treat the agent's PR exactly like a junior dev's" — nothing waived because an AI wrote it). Required status checks + **merge queue** (GitHub merge queue / Graphite / Mergify / Trunk / Aviator — matters more under agents: many agent PRs on the same base → semantic conflicts that pass individually; gotcha: workflows must handle the `merge_group` event). **Mergify counter-narrative** (153k merges, 160 teams): AI-assisted PRs broke `main` ~**half as often** as non-AI PRs — the gate mattered more than the author (single vendor dataset). Autonomous "iterate until CI is green" agents: Codex (`codex exec --full-auto`), Devin, Copilot coding agent, Claude Code GitHub Actions — CI becomes the reward signal directly. Failure mode (documented, arXiv 2605.01471): agent "fixes" CI by weakening it — `expect(x).toBeTruthy()`, `skip`/delete the test, `continue-on-error: true`, edit the workflow YAML. Mitigation: **treat any change to CI config / test files / lint config / coverage thresholds as always-human-review**; Codex hook stack (PostToolUse lint, Stop-hook blocks turn until suite passes) — with a documented hole (hooks only fire for Bash, `apply_patch` edits bypass them). Cost: agent loops multiply CI runs + amplify flaky-test cost; mitigations — affected-tests-only inner loop (<5 min), full suite on merge/deploy only, sharding, ephemeral preview envs.
10. 🟢 **Structural quality & maintainability metrics as a guardrail** — the delta: track codebase erosion as a first-class *per-contribution* metric, because models have no fast reward signal for maintainability (Dex Horthy pass argument). **GitClear "AI Copilot Code Quality" 2025** (~211M changed lines, 2020–2024): copy/paste share 8.3%→12.3%, ≥5-line duplicate blocks ~8× up in 2024, "moved"/refactored lines ~24%→<10%, 2-week churn 3.1%→5.7% — correlational only, CEO says so, confounders (layoffs/seniority) uncontrolled, vendor sells metrics tooling. **GitClear "The Maintainability Gap" 2026** (623M changes, 2023–2026): cross-file function calls −35%, refactoring 21%→3.8%, duplication +81%, copy/paste +41%, error-masking constructs +47%, churn +15%. **CodeScene — Borg & Tornhill peer-reviewed paper** (arXiv 2601.02200, Jan 2026) + whitepaper: **AI assistants increase defect risk by ≥30% when applied to "unhealthy" code** (CodeHealth <7.0/10) — the most defensible single number here; loveholidays case study (added CodeScene "ACE" code-health safeguards → reversed declining health, scaled 0→50% agent-assisted code in 5 months). CodeScene's "6× more accurate than SonarQube" is marketing. Tools: SonarQube/SonarCloud, CodeScene (behavioral code analysis — git history + metrics → hotspots), Code Climate, `radon`/`lizard`, ESLint `complexity`. Guardrail pattern: fail the check / block the agent's yield if the change lowers the health score.
11. 🟢 **Quality frameworks & language-specific QA tooling** — SonarQube **quality gate** adapted: SonarQube 2025.x **"AI Code Assurance"** (label AI-generated code, stricter "Sonar way for AI Code" gate, certification badge) + AI CodeFix + **SonarQube MCP server** (agent queries its own findings). Dominant pattern (convergent community practice, no canonical source or study): expose the **entire per-language QA stack behind one entry point** — `make check` / `just check` / `npm run verify` / an MCP tool — and instruct the agent in `CLAUDE.md` / `AGENTS.md` to run it and fix everything before finishing. Examples: "The Agentic Makefile", `pi-green-loop`, PyQA. Per-ecosystem stacks in the raw file (JS/TS: ESLint/Biome/oxlint, tsc, Vitest, Playwright; Python: ruff, mypy/pyright, pytest, Hypothesis, mutmut, bandit; Rust: clippy, nextest, miri, cargo-mutants, cargo-audit; Java: SpotBugs, PMD, Checkstyle, JaCoCo, PIT, JMH; Go: staticcheck, golangci-lint, govulncheck, gosec; .NET: Roslyn analyzers, Stryker.NET). The agentic delta is **completeness** (every check in the one command), **speed** (sub-5-min → ruff/Biome/oxlint/nextest over slower predecessors), **machine-readable output** (JSON/SARIF), and **MCP exposure**.

## What this means for `src/quality.md` (suggestion, not a decision)

The chapter's planning comment already implies the spine: **quality aspects → methods → tools → challenges**. The research suggests leading with the *challenge* as the motivating frame, then walking the methods in feedback-loop order:

1. **Open with "More code, less understanding"** (§1) as the thesis — comprehension debt, the review-economics inversion, the Anthropic RCT and the 61% no-review figure. This motivates everything else: the response is to *automate and harden the gates* so less rides on the human skim.
2. **The agentic quality loop** — a section (with a mermaid diagram) showing the inner loop: agent writes → deterministic checks (compile / type / lint / SAST §3) → tests incl. mutation/property (§4) → structural-health delta (§10) → browser/E2E self-verify (§5) → only then yield to review. Then the outer loop: AI review layer (§2) → human review retargeted to intent/architecture → CI merge-queue gate (§9) → feature-flagged progressive rollout (§6).
3. **What agents systematically get wrong** — a table drawn from the evidence: weak test oracles (§4), non-functional blind spots (§7), duplication/coupling erosion (§10), guardrail-weakening (§3/§4/§9). Each with its defense.
4. **Design by Contract** (§8) as a forward-looking section, explicitly flagged as emerging/under-evidenced per CLAUDE.md's `Research Note:` convention — cross-link `spec-driven-development.md`.
5. **Tooling reference** (§11) — the "one command / MCP / rules-file self-check" pattern + the per-ecosystem stack table + SonarQube AI Code Assurance.
6. **`Research Note:` paragraphs** where corroboration is partial: the causal-attribution hedge on GitClear/DORA (§1/§10), the vendor-benchmark caveat on AI review efficacy (§2), the absence of effectiveness data for browser self-verification (§5), the single-study basis for contracts-help-LLMs (§8), the one-blog collation of the dramatic performance numbers (§7).

Glossary candidates: comprehension debt, test oracle problem, mutation testing, property-based testing, self-healing tests, merge queue, progressive delivery, Design by Contract, quality gate, SAST/DAST/SCA, consumer-driven contract testing.
