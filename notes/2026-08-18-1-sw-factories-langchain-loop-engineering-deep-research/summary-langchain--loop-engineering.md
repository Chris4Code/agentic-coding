## LangChain — compressed

- 🟢 LangChain (chains) → LangGraph (explicit stateful graph, cycles, checkpointing) → DeepAgents is a **three-generation evolution**, not one static product — the ecosystem itself keeps pushing control back toward the user, which is the chapter's real throughline (per [LangChain's own post](https://www.langchain.com/blog/on-agent-frameworks-and-agent-observability)).
- 🟡 **Not simply "rejected"** — LangGraph is a genuine building block in named factory-style pipelines: **Uber** (Java→Kotlin migration + test generation, reported 21,000 dev-hours saved), **Replit** (core code-gen product, human-in-the-loop), **LinkedIn SQL Bot**, **Elastic** (upgraded from base LangChain to LangGraph). Note Uber *also* dropped a custom coding-assistant build in favor of GitHub Copilot in the same initiative — adoption and rejection coexist even within one company.
- 🟡/🟠 **Abandonment stories are real but scattered**: Octomind ripped LangChain out entirely (source fetch failed — relayed via search synthesis only, treat as approximate); a Hacker News thread gives concrete named complaints (5 layers of abstraction for anything non-trivial, opaque errors, "you only needed string handling + API calls + loops"); a coding-agent-specific piece argues the Planner/Coder/Reviewer "team of agents" pitch specifically doesn't work for coding (403'd — snippet only, thin).
- 🟢 **Best non-Horthy-adjacent corroboration**: Anthropic's own ["Building Effective Agents"](https://www.anthropic.com/engineering/building-effective-agents) independently warns against framework-first building and cites the same abstraction-opacity problem, without naming LangChain.
- **The Horthy "~100 engineers rejected LangChain/CrewAI" claim from the 2026-08-17 research is still single-source at the specific-attribution level** — the `12-factor-agents` README itself never names LangChain/CrewAI directly (only an oblique "plug-and-play crew/langchains" aside). But the *general shape* of the claim (frameworks hit a control-flow abstraction ceiling) is now corroborated by multiple unrelated parties (Octomind, HN, CrewAI critique, Anthropic). **Convergent evidence for the pattern, not confirmation of the specific claim** — word the chapter accordingly if citing it.

## Loop Engineering (factory-level) — compressed

- **Explicit distinction from `basics.md`, stated up front in the raw file**: `basics.md`'s loop engineering is about *one agent's own context window* across turns (token cost). This research is about *many complete agent-loop instances wired into a pipeline* — a different unit of analysis. Both senses are legitimate and both appear in industry sources; the two chapters aren't duplicating each other, they're operating at different levels of the same Harness → Loop → Factory stack.
- 🟢 **Formal vocabulary**: Anthropic's "Building Effective Agents" names the patterns flagged as unresearched in `Software Factory.md` — **orchestrator-workers** (central LLM delegates dynamically-determined subtasks) and **evaluator-optimizer** (generator + evaluator in a loop) — among five workflow patterns total.
- 🟢 **Strongest find this pass — Ona's "Memo" case study** (Ona's own blog, fully primary-sourced): a real software factory, **14 automations across 5 layers** (Planning → Build → Quality → Verification → Operations), scheduled + event-driven triggers, **375 PRs in 10 days, 87% merged with zero human involvement**, remaining 13% escalated via risk-based routing. Gives this book's abstract "many harnessed loops running in parallel" framing hard numbers and a real architecture.
- 🟢 **Best citable quote pair**: Ona's CTO frames the human's role shifting from **"in the loop"** (days 1-3, human directs every step, 8-10 hrs/day) to **"on the loop"** (week 2+, human reviews escalations/metrics and designs new feedback loops, 2-3 hrs/day) — "externalising your intuition into the factory." Also: *"A factory without feedback loops is just a fast builder."* This pair is the cleanest available vocabulary for the book's human-leverage-vs-toil framing, and it's about which loop a *human* is inside — orthogonal to `basics.md`'s token-management loop.
- 🟡 **Named tooling ecosystem extending the bare Ralph loop**: **Ralph Workflow** (composable plan→build→review→fix cycles across multiple agents) and **Nightshift** (dual hardening + feature daemon, "auditable shift logs by morning"). Both explicitly position themselves against the bare single loop as a more primitive baseline — independent evidence the two "loop engineering" senses really are distinct in practice, not just in this book's taxonomy.
- 🟡 **Factory.ai** (already a listed competitor in `Software Factory.md`) defines a factory as a continuous triage→plan→build→test→review→ship→monitor loop, with named enterprise metrics (Chainguard, Groq, Empower, Nav) — vendor-published, not audited, but concrete and citable.
