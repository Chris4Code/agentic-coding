## Per-subtopic findings — compressed

- 🟢 **llama.cpp** — C/C++ on the `ggml` tensor library, maintained by ggml-org / Georgi Gerganov. GGUF = single self-describing, `mmap`-ed model file. Huge backend list (CUDA, HIP/ROCm, Metal, SYCL, Vulkan, OpenCL, CANN, MUSA, CPU with AVX/AMX/NEON). `-ngl N` = CPU+GPU layer offload (runs models bigger than VRAM, slowly). `llama-server` = single binary, OpenAI-compatible API. Concurrency = fixed `--parallel N` KV slots + continuous batching, **no PagedAttention** → degrades under load faster than vLLM. Speculative decoding via `--model-draft`.
- 🟢 **Ollama** — MIT, Ollama Inc. (YC-backed). Go CLI/daemon, Docker-like registry + Modelfile. Started as a llama.cpp wrapper; since 2025 ships **its own ggml-based engine** (used for newer/multimodal models) alongside the llama.cpp path. MLX path for Apple Silicon (preview, 2025→2026). Auto-unloads idle models. OpenAI-compatible `/v1`. Overhead vs raw llama.cpp is small per-request; the real cost is conservative defaults + lag on brand-new models (🟡). MLX speed numbers 🟠.
- 🟢 **vLLM** — Berkeley; PagedAttention (Kwon et al. SOSP '23, already in the book's notes). Continuous batching, tensor/pipeline/data/expert/context parallelism, automatic prefix caching. Fast path = safetensors + AWQ/GPTQ/FP8; GGUF loading exists but experimental. Pre-allocates `gpu_memory_utilization` **default 0.9** of the card → OOMs on 8–16 GB, no RAM offload. Beats llama.cpp on concurrency/throughput with the model fully in VRAM; unusable when the model doesn't fit or on a casual single-user box. Alternatives: SGLang (RadixAttention, better on shared prefixes), HF TGI (reportedly maintenance-mode late 2025 — 🟠, verify), TensorRT-LLM (fastest on NVIDIA, heavy).
- 🟡 **Consumer PC hardware (CPU + RAM)** — decode is **memory-bandwidth-bound**, not FLOPS-bound: tok/s ≈ usable bandwidth ÷ active-weight-bytes-per-token. Dual-channel DDR5 desktop ≈ 50–90 GB/s usable; quad/8-channel workstation ≈ 200–500 GB/s; discrete GPU 450 GB/s–1.8 TB/s; datacenter HBM 3–8 TB/s. So a desktop CPU has ~10–30× less bandwidth than a good GPU. Realistic CPU tok/s (Q4, llama.cpp): 7–8B ≈ 3–10, 13–14B ≈ 2–5, 30B dense ≈ 1–3 (too slow to be interactive), 70B ≈ 1–2. **MoE flips this**: a 30B-A3B (3B active) runs at interactive speed on CPU/APU because cost tracks *active* params — the main reason CPU inference got practical in 2025–26 (needs RAM for all experts though). Bandwidth physics 🟢, tok/s ranges 🟡.
- 🟡 **Consumer GPUs & dedicated-VRAM case** — dedicated GDDR is 5–20× system RAM bandwidth and uncontended; VRAM bandwidth sets tok/s, VRAM capacity sets max model/context at full speed; spilling to RAM collapses toward CPU numbers. Practical "useful local coding model" line ≈ **20–24 GB VRAM** (32B dense at usable context). Prereqs: 850–1000 W PSU for one 5090 (12V-2×6/12VHPWR connector, documented melting), triple-slot ~300–360 mm cards, mainstream desktop CPUs give ~20–28 PCIe lanes → one x16 + one x4, so 2+ GPUs / NVLink for vLLM tensor-parallel needs HEDT (Threadripper/Xeon-W/EPYC). PSU/connector facts 🟢, GB-per-model thresholds 🟡.
- 🟢/🟡 **NVIDIA + CUDA** — dominance = every engine targets CUDA first + day-one model support + TensorRT-LLM + Blackwell native FP4. Drawbacks: VRAM segmentation (24 GB stuck at 3090/4090, 32 GB at 5090, then a price cliff to workstation/datacenter), datacenter driver licensing (GeForce EULA restricts datacenter use), lock-in. Cards for local coding + **Aug 2026 street prices (all inflated by the DRAM crunch, volatile)**: RTX 3090 24 GB used ~$700–1,000; RTX 4090 24 GB ~$2,500–3,800 (disc., was $1,599); RTX 5090 32 GB ~$4,000–4,500 (was $1,999); RTX PRO 6000 Blackwell 96 GB **MSRP doubled to ~$16,000**; plus RTX 2000/4000 Ada (16/20 GB ECC, 70–130 W), RTX PRO 2000 Blackwell 16 GB. Specs/existence 🟢, prices 🟡-volatile.
- 🟡 **AMD + ROCm** — Linux-first; ROCm 7 line (2025→). Officially-supported consumer cards = RX 7900 XTX/XT/GRE + Radeon PRO W7900/W7800; RDNA4 (RX 9070) added later; others via `HSA_OVERRIDE_GFX_VERSION`. Windows: HIP SDK + llama.cpp/Ollama builds exist but PyTorch-ROCm / vLLM / SGLang are effectively Linux-only. Vulkan is the pragmatic AMD-on-Windows path. Phoronix (Oct 2025): ROCm ahead on prefill, Vulkan competitive on decode — the two are close now. Prices (volatile): RX 7900 XTX 24 GB ~$900; RX 7900 XT 20 GB ~$700–970; RX 9070 XT 16 GB ~$730; PRO W7900 48 GB ~$3,500–4,000. AMD docs 🟢, Phoronix 🟢, prices 🟡/🟠.
- 🟡 **Intel + SYCL** — oneAPI/SYCL + IPEX-LLM. llama.cpp has an Intel-contributed SYCL backend (Arc discrete + iGPU 11th-gen+); Ollama support lags; Vulkan is an alternative. Smallest ecosystem, heavy toolchain, models validated on Arc last. Real Arc cards: A770 16 GB, B580 12 GB, **Arc Pro B50 16 GB ($349 launch)**, Arc Pro B60 24 GB (~$500–600, partner dual-B60 48 GB). Intel/llama.cpp docs 🟢, Arc Pro pricing 🟡.
- 🟡 **Vulkan** — llama.cpp's vendor-neutral compute backend; any conformant Vulkan 1.2+ driver, no vendor SDK. Slower than CUDA on NVIDIA (use CUDA there); ~within single-digit-to-low-tens-% of ROCm/SYCL by 2025–26 and much easier to set up. Choose it for: AMD-on-Windows, Intel Arc/iGPU without oneAPI, mixed-vendor multi-GPU, unsupported-but-Vulkan-capable cards. Not in vLLM/SGLang. llama.cpp docs + Phoronix 🟢, gap framing 🟡.
- 🟢/🟡 **Apple Metal / MLX** — two stacks: llama.cpp Metal (GGUF, mature) and Apple's **MLX** (+ mlx-lm / mlx-vlm), faster on M-series → adopted by Ollama & LM Studio. Unified memory = no PCIe copy, no separate VRAM. Apple bandwidth figures (🟢): M4 Pro 273 GB/s, M4 Max 410/546 GB/s, M3 Ultra "over 800 GB/s" / up to 512 GB. `recommendedMaxWorkingSetSize` → macOS gives GPU ~65–75% of RAM by default (128 GB → ~96 GB usable), raisable via `iogpu.wired_limit_mb` (🟡). M3 Ultra 512 GB *holds* DeepSeek-R1 671B @ 4-bit but only ~15–18 tok/s (🟡). Even M3 Ultra ≈ half a 4090's bandwidth; a 5090 ≈ 2× M3 Ultra.
- 🟡 **AI-Workstations (unified memory)** — big capacity, bandwidth ~10× below discrete VRAM → big *dense* models load but crawl; MoE is the sweet spot. **DGX Spark (GB10)**: 128 GB LPDDR5X, **~273 GB/s** (criticized), launched $3,999 Oct 2025 → **raised to ~$4,699** Feb 2026 (LPDDR5X supply). **AMD Ryzen AI Max+ 395 "Strix Halo"**: up to 128 GB, ~256 GB/s, Radeon 8060S iGPU; Framework Desktop 128 GB ≈ $1,999 — cheaper than DGX Spark for same capacity, slightly less bandwidth. **Mac Studio M3 Ultra**: 512 GB @ ~800 GB/s — highest capacity *and* bandwidth of the three, ~$10k (+ 2026 availability caveat). Core specs 🟢, tok/s 🟠.
- 🟢/🟡 **Datacenter GPU stacks** — NVIDIA A100 40/80 GB (~2 TB/s), H100 80 GB (3.35 TB/s), H200 141 GB (4.8 TB/s), B200 ~180–192 GB (~8 TB/s), GB200 superchip; NVLink 900 GB/s (Hopper) → 1.8 TB/s (Blackwell), NVSwitch → NVL72 = 72 GPUs as one NVLink domain. AMD Instinct MI300X 192 GB / 5.3 TB/s, MI325X 256 GB (announced 288 GB — discrepancy noted), MI350 series 🟠. Needed for: frontier MoE (~670B+) via TP/PP/EP, many concurrent users, higher single-stream tok/s. Costs: H100 ~$25–30k+ to buy, 8-GPU nodes $250–400k+, 10–15 kW, rack/cooling. Cloud rental (2026, volatile 🟡): H100 ~$1.5–3.5/GPU-hr neocloud, H200 ~$2.3–4.5, B200 ~$4.5–7, MI300X ~$1.7–3. Buy-vs-rent break-even ~50–70% sustained util over 1–2 yr. Specs 🟢, pricing 🟡.
- 🟡 **Cross-cutting: 2026 DRAM/GDDR7/HBM supply crunch** — AI datacenter demand crowding out consumer supply; concrete effects well-corroborated (RTX PRO 6000 MSRP doubled, RTX 5090 ~2–2.3× MSRP, DGX Spark +$700, Apple reportedly dropped 512 GB Mac Studio 🟠). For the chapter: give prices as ranges dated "as of 2026, inflated by the DRAM shortage", avoid hard MSRPs.

## What this means for `src/local-models.md` (suggestion, not decided)

The chapter outline's structure holds up well against the research. Concrete proposals:

1. **Lead the Hardware section with the memory-bandwidth-bound framing** — it's the single idea that explains every downstream choice (why VRAM > FLOPS, why CPU is slow, why unified-memory boxes crawl on dense models, why MoE changes everything, why datacenter HBM matters). Put it right after `## Hardware`, before `### PCs`. Good candidate for a mermaid diagram: bandwidth ladder (DDR5 desktop → unified memory → consumer GDDR → datacenter HBM) with representative tok/s.
2. **`### PCs`** (`low cost, available hardware, performance issues`): CPU+RAM inference, the 50–90 GB/s dual-channel ceiling, realistic tok/s table, and the MoE escape hatch. Note the 2026 RAM price inflation.
3. **`### Consumer GPUs and Low-Level SW-Stacks`**: keep the "dedicated VRAM advantage / PSU + workstation prerequisites" framing verbatim from the CONTENT-KEY-SUBJECTS — the research backs it. The 16 GB vs 20–24 GB threshold is the practical takeaway.
4. **Per-vendor subsections** (`#### NVIDIA + CUDA`, `#### AMD + ROCm`, `#### Intel + SYCL`): each gets advantages/drawbacks + a small GPU table with VRAM/bandwidth/price-range-with-date. Recurring theme: CUDA = universal + first; ROCm = Linux-first, narrower matrix, catching up; SYCL = smallest, roughest.
5. **`#### Vulkan`** and **`#### Apple Metal`**: frame both as "versus the vendor stacks" per the CONTENT-KEY-SUBJECTS. Vulkan = universal fallback, near-ROCm now. Metal/MLX = unified-memory story, MLX faster than Metal on Mac.
6. **`### AI-Workstations`** (`Shared Memory, Performance`): DGX Spark vs Strix Halo vs Mac Studio table (capacity / bandwidth / price), and the blunt takeaway — these are for running models that don't fit 24–32 GB, not for speed.
7. **`### Datacenter GPU Stacks`**: H100/H200/B200/MI300X table, NVLink/NVSwitch, buy-vs-rent economics, when a self-hoster actually needs them (rarely, for a single dev).
8. Add a **`Research Note:`** paragraph wherever the chapter states a 2026 price (volatile, crunch-inflated) and on any tok/s figure (secondary ranges, not primary benchmarks), per CLAUDE.md's evidence-quality convention.
9. **Glossary** additions likely needed: GGUF, ggml, PagedAttention, continuous batching, speculative decoding, layer offload, unified memory, memory bandwidth wall, ROCm, SYCL, oneAPI, HIP, Vulkan backend, MLX, NVLink/NVSwitch, HBM, tensor parallelism, quantization (defer detail to pass 2).
